# expo-headless-mcp

MCP-сервер, который даёт ИИ **скриншоты Expo/React Native приложения без эмулятора, телефона и браузера**.

## Как это устроено
Metro + Expo Go требуют нативный рантайм, поэтому вместо них:
1. `esbuild` собирает проект (`App.*` или `main`), подменяя `react-native` на лёгкий шим (`src/shim/rn.js`), а нативные пакеты (`expo-*`, `react-native-*`) — на заглушки.
2. Приложение запускается в Node, React рендерит в собственное дерево (`react-reconciler`).
3. Раскладка — Yoga (тот же flexbox-движок, что в RN), отрисовка — Skia (`@napi-rs/canvas`) → PNG.

Ограничения: это приближение, а не настоящий iOS/Android — шрифты, тени, анимации и нативные модули не совпадают пиксель-в-пиксель; `expo-router`/`react-navigation` не поддерживаются; состояние сбрасывается при `refresh_screen`.

## Инструменты
- `refresh_screen` — пересобрать и показать экран (`projectPath`, `entry`, `width`, `height`, `scale`, `reload`)
- `click_screen` — тап по `x,y` или `target` (testID / текст), `long`, `alert:<кнопка>`
- `type_text` — ввод в TextInput (`target`/`x,y`, `submit`, `append`)
- `scroll_screen` — прокрутка под `x,y`
- `describe_screen` — текстовый список элементов + предупреждения о вёрстке (наложение, обрезанный текст, выход за экран)

## Подключение
```
claude mcp add expo -e EXPO_PROJECT=/path/to/app -- npx -y expo-headless-mcp
```
Тесты: `node test/smoke.js` (скриншоты в `test/out/`), `node test/mcp.js`.

## Автопроверка
- `auto_test` — несколько раундов: перезапуск, заполнение всех полей разными данными (пусто, неверно, верно, очень длинно, спецсимволы), нажатие каждой кнопки/переключателя (со скроллом), закрытие алертов. Отчёт: крэши, ошибки/предупреждения консоли, наложения/обрезанный текст/выход за экран, кнопки без эффекта + скриншоты проблем.
- Сервер отдаёт ИИ встроенные `instructions`: после любого изменения кода — пересобрать, проверить руками, прогнать `auto_test`, чинить и повторять до чистого прогона.
- MCP-промпт `verify_changes` запускает то же по команде.

## Режим реального устройства (необязательно)
Кроме встроенного рендера ИИ может управлять **Expo Go на Android-эмуляторе или телефоне по USB** через `adb` (Windows, macOS, Linux), а также **в запущенном iOS-симуляторе** (только macOS с Xcode; для касаний нужен Facebook idb). Физический iPhone не поддерживается — откройте Expo Go на нём сами.

Правила безопасности:
- **Ничего не подключено / нет adb →** ИИ так и скажет, ничего не изменит и посоветует проверить приложение самому (или продолжить в headless-режиме).
- **Отладка по USB выключена →** объяснит, как включить, и заранее предупредит, что будет нажимать, вводить текст и скроллить на телефоне.
- **Сначала согласие.** Спрашивает перед управлением физическим телефоном, перед установкой Expo Go и перед заменой Expo Go другой версии SDK (нужная версия берётся из официального списка Expo; при понижении сначала удаляется старая — это сказано в вопросе). **При отказе ничего не делается и повторов не будет.**
- Трогает **только Expo Go** (перед каждым действием проверяется, что он на переднем плане). `auto_test` работает только в headless-режиме; не-ASCII текст через adb ввести нельзя.

**Статус:** Android проверен автором на реальном телефоне и тестами на подставном `adb`; iOS — только тестами на подставных `xcrun`/`idb`, на настоящем Mac ещё не запускался.
